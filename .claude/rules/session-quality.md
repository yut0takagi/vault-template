# セッション品質ルール

Claude Code セッションでよく観測される失敗パターン（restart-cluster / edit-thrashing / error-loop）を防ぐための行動原則。

- **出力前にダブルチェック**: 提示する前に検証。最初の応答が明らかに間違っていることが多く、ユーザーが秒単位で訂正している
- **訂正時は再読**: ユーザーから訂正されたら一度止まり、相手の発言を引用して確認してから進める
- **行き詰まりは相談**: 同じ手法のリトライを繰り返さず、試したことを要約してユーザーに方針を聞く
- **編集前に全文読み**: 変更を計画してから1回で完結。同じファイルを3回以上編集したら手を止めて要件を再確認する
- **直前メッセージを再読**: 応答前にユーザーの最後のメッセージを読み直し、すべての指示に完全に従う
- **早く動く**: 変更前に3〜5ファイル以上読まない。基本理解→変更→反復のサイクルで進める
- **2回連続失敗で戦略変更**: 同じアプローチの再試行をやめて別の戦略に切り替える。何が失敗したか説明する
- **数ターンごとに元の依頼を再読**: 目的からずれていないか確認する
